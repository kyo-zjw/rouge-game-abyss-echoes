## 0. 一句话总思路

**一张好用的技能特效 = 程序化绘制保底 + 贴图升级 + 统一风格锚点 + 严格抠图 + 最小侵入接入（有图用图、无图自动回退、回退行为与原来完全一致）。**

流程：**文生图黑底展示稿 → 用户确认 → 亮度抠图透明底 → 注册资源 → vfx.js 贴图优先分支 → 测试 → 交付试玩**。

按 "成品定义 → 主体 → 构图 → 视觉语言 → 禁止项" 顺序写，**每句可观察、可核验**，不堆热词：



```

<构图：主体位置、占画面比例、朝向/动线、附加元素（火星/碎晶/光点）>。
整体干净利落、低复杂度、柔和自发光，无复杂背景、无杂物，适合网页Canvas渲染。
```

要点：



* **阶段拆分**：一个技能至少拆 2 张 —— 弹道 / 本体版 + 命中 / 爆发版（区域技能拆：地面领域版 + 激活版）。分开发，方便命中复用。

* 深色近黑底展示（火焰 / 冰晶在黑底上最醒目，也便于亮度抠图）。

* 图片内文字一律禁止（游戏特效不需要文字）。

## 3. 素材管线（生成 → 确认 → 抠图 → 入库）



1. **生成**：`image_gen` 生成黑底展示稿（2048×2048 输出，按 1024 请求即可），用 RichMediaCard 交付给用户确认。

2. **确认**：用户点头后，`curl.exe -L -o` 下载原图到 `.creative-design/<task>/raw_*.png`。

3. **抠图（v2，2026-10 起用这套）**：黑底发光物**不要**再用「纯亮度 alpha」（`clamp((t-10)/240)**0.85`）——它会把黑底噪点映射成 alpha 3~48 的近黑薄纱，`source-over` 叠到场景上就是用户看到的「淡淡的黑色背景框」。

   改用**黑点减法 + 反合成去污 + 硬清零**，脚本：`.creative-design/mage-vfx-rework/key_v2.py`（可直接改 `JOBS` 表复用）：

   * 估算黑底基线 `lo`：整图亮度 20% 分位 + 8，夹在 `[14, 52]`；
   * `a = clamp((t - lo) / (215 - lo), 0, 1) ** gamma`，`gamma` 0.92~0.95；
   * **硬清零**：`a <= cut` 置 0，其余重归一化 `(a - cut) / (1 - cut)`（`cut` 弹道/命中 0.08~0.10，地面领域 0.12）；
   * **反合成去污**：`c = (pixel - (1-a)*lo) / max(a, 0.12)`，去掉半透明边缘里混进来的黑；
   * 预乘 alpha 缩放 → 反预乘（`a < 0.05` 不放大噪点）→ 二次硬清零（`alpha < 22 → 0`）；
   * 包围盒裁剪 + 3~5% 内边距，输出 512×512（特效）/ 128×128（图标）。

   验收标准：`faint`（`0 < alpha <= 48` 的像素占比）**< 5%**，且棋盘格/实景合成里看不到方块暗框。旧脚本 `key_impact.py` / `key_flight.py` / `key_fire2.py` 保留作历史对照（它们的输出即这次修掉的那批）。

   * 如果地面领域边缘出现「一圈硬边」（像结界外壳），在 alpha 上再乘一个从 `0.62r` 到 `1.0r` 的 `smoothstep` 径向衰减，让边缘自然消散（暴风雪就是这么修的）。

   * 生成棋盘格 / 实景预览，肉眼检查：无黑边残留、无整图雾感、主体 / 拖尾完整。

1. **入库**：透明 PNG 放 `assets/fx/<skill>_<phase>.png`；画布持久化衍生资产（`+create`，`<source_ids>` 填来源展示稿 item id）。

2. 命中阶段若最终要 "贴着身体回贴"（如护盾、光环），同一套流程，抠图后注意 Alpha 检查。

## 4. 代码接入范式（贴图优先 + 自动回退）

**原则：有图用图；无图 / 未加载时行为与修改前完全一致（Assets.draw/entry 返回 false 即回退）。**



1. **注册资源**（`js/content.js` → `CONTENT.assets`）新增 `fx` 组：



```
fx: {
  fireball_impact: 'fx/fireball_impact.png',
  fireball_flight: 'fx/fireball_flight.png'
}
```

⚠️ **漏注册 = 静默回退程序化 = 看起来 "没生效"**（本项目踩过）。



1. **vfx.js 对应绘制函数**里用 `Assets.entry('fx', key)` 取图并判断 `ready && img`：

* 弹道：`drawProjectile()` 的 style case（fire/pyro 共用一个 case）

* 命中爆炸：`_burst()` 的 style 分支

* 地面区域：`drawZone()` 的 kind 分支（暴风雪 / 烈焰风暴用）

* 护盾 / 光环：`_aura`/ 护盾绘制处

1. **贴图绘制要点**：

* **朝向**：先看贴图主体在画面哪个位置！本项目弹道图主体偏左、拖尾在右 → 直接对齐运动方向会 "尾巴朝怪"，需要 `ang + Math.PI` 翻转。**每个新贴图先确认主体位置再决定旋转 / 翻转**。

* **大小**：由半径推导（如 `sz = r * 3.4`），要固定大小就把 `lvl` 里 `size` 字段统一（本项目 fireball 五级统一 `size: 10`，爆炸 aoe 仍随等级）。

* **生命动画**：`grow = 0.62 + 0.38*e`（由小放大）、`alpha = (1-k)*0.95`（渐隐）、可加 `wob = 1 + 0.05*sin(t*14)` 呼吸。

* **混合模式**：彩色贴图用 `source-over`（`lighter` 会过曝）；程序化增强层（闪光 / 冲击环 / 烟团）留在 `lighter` 下。

* **避免重复层**：贴图自带拖尾 / 火星时，跳过对应程序化层；保留增强动感层（地面闪光、烟团）—— 是否留冲击环由用户喜好决定。

* **回退保底**：贴图分支用 `if (hasImg) { ...; break/return }` 结构，无图直接走原程序化。

1. 命中爆炸（`_burst`）：`style === 'fire'/'pyro'` 且有贴图时以贴图为主体，可跳过光刺 / 碎片 / 火舌等高频粒子层。

## 7. 已踩的坑（下个对话避免重复）



1. **fx 组漏注册** → 引擎静默回退程序化，现象是 "看起来没替换"。改完先查 `CONTENT.assets.fx` 两项都在。

2. **贴图主体不在中心** → 朝向不能无脑对齐 +x；先确认主体在贴图哪侧，再决定是否 `+π` 翻转或旋转。

3. **黑底 jpeg 有压缩噪点** → 亮度阈值 `TH_LOW=10` 起步，gamma<1 保住暗部纹理；抠完必须看棋盘格预览（防整图雾感）。

4. **lighter 让彩色贴图过曝** → 贴图层单独 `source-over`，程序化增强层才用 `lighter`。

5. **双拖尾** → 贴图自带拖尾时跳过程序化拖尾段。

6. **size 随等级变** → 要固定弹体大小，直接统一 `lvl` 里 `size` 字段（爆炸 aoe 留在各自 lvl 值里）。

7. **残留「淡黑色方框」**（v0.9 修掉的老问题）→ 纯亮度 alpha 会把背景噪点映射成 alpha 3~48 的近黑薄纱，`source-over` 叠上去就是一块略暗的方框。判据：`0 < alpha <= 48` 的像素占比。v1 素材是 29%~53%，v2 修完是 1%~4%。验收时务必把素材按游戏里的尺寸、`source-over` 叠到真实场景背景上看，而不是只看棋盘格。

8. **去污不能只抠不反合成** → 半透明边缘的 RGB 里混着黑色背景，直接用会得到一圈脏边；v2 用 `c = (pixel - (1-a)*lo) / a` 反合成。

9. **地面领域的「硬边圆环」** → 贴图自带一圈冰墙/结界边时，在 alpha 上乘 `smoothstep(1.0 → 0.62)` 的径向衰减，别指望靠调低整体透明度解决。

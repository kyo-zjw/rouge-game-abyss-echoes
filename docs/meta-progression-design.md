> 状态：**已实现**。本文件描述三槽存档、金币、三系天赋树与深渊侵蚀的最终规格，数值与 `js/talents.js`、`js/main.js` 保持一致。

## 0. 已确认的边界

| 决策 | 结论 |
|---|---|
| 天赋与卡池 | 天赋**只加强度**，不把 15 个职业技能塞进单局卡池 |
| 三系划分 | 战士：武器 / 狂怒 / 防护；法师：火焰 / 冰霜 / 奥术 |
| 金币产出 | 小怪 3%、精英 12%、Boss 30/50/80/120/200、通关 +100；死亡不清空 |
| 存档槽 | 3 个槽，**每槽绑定 1 个职业 + 1 个形象**；同职业允许重复建槽 |
| 永久属性 | **只来自天赋树**；不做独立账号等级、不做可继承遗物 |
| 树规模 | 6 环、3 分支、每分支 11 节点，共 **33 节点 / 93 级**；多级节点；可洗点 |
| 平衡 | 数值封顶 + **深渊侵蚀**：天赋点得越多，敌人略微加强 |

## 1. 金币经济

### 1.1 产出

| 来源 | 数量 | 说明 |
|---|---:|---|
| 普通小怪 | 3% 掉 1 金 | 金币是物理拾取物，吃磁吸范围 |
| 精英 | 12% 掉 3 金 | 同上 |
| 第 1~5 阶 Boss | 30 / 50 / 80 / 120 / 200 | 击杀时在脚下爆出 2~8 枚 |
| 通关 | +100 | 击杀第 5 阶 Boss 时结算 |

- 金币落地不消失；跑图漏捡的，在死亡 / 通关结算时**自动收进本局金币**，保证「死亡全留」。
- 本局金币只在**结算时**写入槽位，避免每捡一枚写一次 `localStorage`。
- HUD 显示本局已拾取金币；天赋页显示槽位总金币。
- `?demo=1` / `?showcase` / 平衡脚本跑的是**直接模式**，不读写任何槽位，避免污染存档。

### 1.2 一局收入估算

按「小怪 3%、每只 1 金」估算：

| 局内 | Boss 金 | 小怪金 | 通关奖励 | 合计 |
|---|---:|---:|---:|---:|
| 2 分钟死亡 | 30 | ~2 | 0 | ~32 |
| 4 分钟死亡 | 80 | ~8 | 0 | ~88 |
| 6 分钟死亡 | 160 | ~14 | 0 | ~174 |
| 8 分钟死亡 | 280 | ~21 | 0 | ~301 |
| 10 分钟通关 | 480 | 30~75 | 100 | **610~655** |

### 1.3 天赋花费

| 节点类型 | 每级费用 | 3 级合计 |
|---|---|---:|
| 核心 | 50 / 75 / 110 | 235 |
| 技能 | 65 / 95 / 135 | 295 |
| 生命 | 50 / 75 / 110 | 235 |
| 力量 | 60 / 90 / 130 | 280 |
| 功能 | 55 / 80 / 115 | 250 |
| 终极 | 700 | 700 |

- **单分支满**：235 + 295×6 + 235 + 280 + 250 + 700 = **3470 金**。
- **三系全满**：**10410 金**。
- 按每次完整通关 ~650 金：一系满约 **5 次通关**，三系全满约 **15 次通关**；如果常年 8 分钟死，一系约 **10 局**。
- **洗点**：返还该槽已投入金币的 **80%**（向下取整），可反复洗，但每次亏 20%。

## 3. 天赋树结构

### 3.1 圆盘布局

- 圆心是职业徽记，不是可购买节点。
- 外圈三等分，每 120° 一个分支，分支之间留 4° 视觉间隙。
- 每个分支 6 环，节点数 `1 / 2 / 2 / 2 / 3 / 1`，共 11 个节点。
- 3 分支 × 11 = **33 个节点**，可投入 **93 级**（每分支 31 级）。
- 6 环半径按 `0.18 / 0.33 / 0.48 / 0.63 / 0.79 / 0.96 × R` 分布；节点半径约 `R × 0.058`（720p 约 15px、1080p 约 20px），悬停放大 1.12 倍。
- 分支名与进度放在左侧信息卡和悬停提示里，外圈只保留节点，避免小窗口文字压到节点。

单分支节点位：

| 环 | 节点位 | 角度偏移 | 类型 | 前置 |
|---|---|---|---|---|
| 1 | 核心 | 0° | 核心 | — |
| 2 | 技能 1 | -16° | 技能 | 核心 |
| 2 | 生命 | +16° | 生命 | 核心 |
| 3 | 技能 2 | -20° | 技能 | 技能 1 |
| 3 | 技能 3 | +20° | 技能 | 生命 |
| 4 | 力量 | -14° | 力量 | 技能 2 |
| 4 | 技能 4 | +14° | 技能 | 技能 3 |
| 5 | 技能 5 | -26° | 技能 | 技能 4 |
| 5 | 跨技能 | 0° | 技能 | 技能 4 |
| 5 | 功能 | +26° | 功能 | 力量 |
| 6 | 终极 | 0° | 终极 | 技能 5 ≥ 2 级 且 功能 ≥ 2 级 |

- 前置只要求 **1 级**即可点亮下一节点；终极要求两个 5 环节点各 **2 级**。
- 三系共享金币，可跨系投资；**终极节点不互斥**，但 700 金/个，全点代价很高。
- 节点购买顺序只受前置限制，不限制「必须先点满一系」。

### 3.2 节点效果（聚合到玩家面板）

| 效果字段 | 含义 | 出现位置 |
|---|---|---|
| `branchDmg` / `branchCdr` / `branchArea` | 本系全部技能伤害 / 冷却 / 范围 | 核心、终极 |
| `dmgPct` | 全部伤害 | 力量节点 |
| `hpPct` | 最大生命 | 生命节点、部分终极 |
| `armorAdd` / `speedAdd` / `regenAdd` / `magnetAdd` | 护甲 / 移速 / 每秒回复 / 拾取范围 | 功能节点、终极 |
| `cdrPct` / `areaPct` / `xpPct` / `goldPct` | 全局冷却 / 技能范围 / 经验 / 金币 | 功能节点 |
| `vsSlowed` | 对**减速目标**的额外伤害（v0.8） | 冰霜「霜噬」 |
| `skills[sid]` | 单个技能的 `dmg / cd / area / width / duration / shield / buff / dot / heal / knock / slow / vuln / dist / internal` | 技能节点、跨技能节点 |

- 聚合顺序：职业基础 → 通用被动 → 临时增益 → 天赋（`Player.recalc()`）。
- 冷却总上限 60%，技能范围总上限 +100%；`cd` / `area` 等技能修正走 `skillStats()`，不直接改 `CONTENT`。
- 未点亮任何节点时，`Talents.bonuses()` 返回空对象，`skillStats()` 直接返回基础数值对象（不额外分配）。

### 3.3 深渊侵蚀

- `stacks = min(8, floor(总天赋等级 / 10))`；敌人生命 `× (1 + 0.012 × stacks)`、伤害 `× (1 + 0.005 × stacks)`。
- 满树 93 级 = 8 层：**+9.6% 生命 / +4% 伤害**。
- 定位是「别让满树完全无脑」的轻量补偿：旧版 +2.5%/+1% 会把整棵树的收益吃掉一半，已下调。
- 天赋页与槽位卡都会显示当前层数与加成；`?erosion=0` 可关闭（平衡脚本常用）。

## 4. 数据与存档

### 4.1 槽位结构

```json
{
  "version": 1,
  "active": 0,
  "slots": [
    {
      "id": 0,
      "classId": "mage",
      "skin": 1,
      "difficulty": "normal",
      "gold": 777,
      "talents": { "fire.core": 3, "fire.skill1": 2 },
      "stats": {
        "normal":   { "time": 601, "kills": 3700, "level": 44, "classId": "mage" },
        "hardcore": { "time": 0, "kills": 0, "level": 0, "classId": "mage" }
      },
      "totals": { "runs": 12, "wins": 4, "kills": 9300, "seconds": 4100, "goldEarned": 2840 },
      "createdAt": 1760000000000,
      "lastPlayed": 1760100000000
    },
    null,
    null
  ]
}
```

- 存储 key：`abyss.slots.v1`；难度偏好单独存 `abyss.diff.v1`；旧最佳记录 `abyss.best.v3` 会迁移到槽 1，旧 key 保留不删。
- 读档时 `normalizeSlot()` 会过滤非法职业、负数金币、未知节点 id 与越界等级，坏存档降级为空槽而不崩溃。
- 直接模式（`?demo=1`、平衡脚本）不创建、不读取、不写入任何槽位。

### 4.2 结算

- 死亡或通关只结算一次（`settled` 标记），先收编地上金币，再计入 `totals` 与最佳记录。
- 最佳记录按难度分开（`stats.normal` / `stats.hardcore`），比较 `time` 再比 `kills`。

## 5. 界面状态

| 状态 | 进入方式 | 关键操作 |
|---|---|---|
| `title` | 启动 | 空格 / 回车 / 点击 → 槽位页 |
| `slots` | 标题、天赋页返回 | 数字键 1~3 或点击选槽；删除需二次确认 |
| `classselect` | 选空槽 | 1 战士 / 2 法师；Tab 切难度；Esc 返回 |
| `skinselect` | 选职业后 | 1 / 2 选形象；空格确认；Esc 返回 |
| `talent` | 建槽完成、点已有槽、死亡后按 T | 点击节点升级；R 洗点（二次确认）；Enter 开局 |
| `playing` | 开局 | 移动 + 空格位移；P / Esc 暂停 |
| `levelup` | 升级 | 1/2/3 或点击选卡；Tab / 左右切换悬停 |
| `paused` / `dead` / `win` | 对应事件 | P / Esc 继续；R 重开；T 回天赋树 |

- 天赋页左侧信息卡：分支进度、永久属性、深渊侵蚀；行数变化时高度自动推导，不会与最后一行叠字。
- 悬停节点显示：当前效果、下一级效果、升级花费、前置要求与缺失项。

| 参数 | 作用 |
|---|---|
| `?slot=1..3` | 启动时选中对应槽位 |
| `?tree=1` | 直接进入当前槽的天赋树 |

## 7. 测试与验收

- `node test/unit.js`：槽位增删改查、洗点返还、天赋聚合、节点前置、存档迁移、UI 渲染不报错。
- `node test/balance.js [局数] [both|warrior|mage] [normal|hardcore]`：内置 AI 的回归扫描，`TALENTS=0|50|70|100|full` 选天赋档。
- 验收重点：
  - 三槽独立：金币 / 天赋 / 职业 / 形象 / 记录互不串档。
  - 洗点后 `totalRanks` 归零、金币按 80% 返还。
  - 满树 93 级时侵蚀为 8 层（+9.6% / +4%）。
  - 坏存档、旧存档、直接模式都不崩溃。

## 8. 已知边界 / 下一步

- 没有商店、成就、每日挑战；金币目前只用于天赋树。
- 天赋树只在菜单绘制，33 节点 + 连线，开销可忽略。
- 洗点只返还金币，不返还已点出的「历史最高侵蚀」——侵蚀始终按当前等级实时计算。
- 后续若要加「重置整槽」「天赋预设」，存档结构已预留 `version` 字段。

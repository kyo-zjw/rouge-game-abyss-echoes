# 深渊回响 v0.6 设计稿：三槽存档 + 职业天赋树

> 状态：**已实现（v0.6，2026-10-22）**。本文把「金币 → 天赋树 → 永久成长」和「本地三槽存档」拆成可实现的规格；数值以本文为准，实现中的差异已写在 §8.7。

## 0. 本轮已确认

| 决策 | 结论 |
|---|---|
| 天赋与卡池 | 天赋**只加强度**，不改 15 技能升级卡池 |
| 三系划分 | 战士：武器 / 狂怒 / 防护；法师：火焰 / 冰霜 / 奥术 |
| 金币产出 | 小怪 3%、精英 12%、Boss 30/50/80/120/200、死亡全留 |
| 存档槽 | 3 个槽，**每槽绑定 1 个职业**；同职业允许重复建槽 |
| 永久属性 | **只来自天赋树**，不做独立账号等级、不做可继承遗物 |
| 树规模 | 6 环、3 分支、每分支 10 节点，共 **30 节点**；多级节点；可洗点 |
| 平衡 | 数值封顶 + **深渊侵蚀**：天赋点越多，敌人略强 |

## 1. 金币经济

### 1.1 产出

| 来源 | 数量 | 说明 |
|---|---:|---|
| 普通小怪 | 3% 掉 1 金 | 金币是物理拾取物，吃磁吸范围 |
| 精英 | 12% 掉 3 金 | 同上 |
| 第 1~5 阶 Boss | 30 / 50 / 80 / 120 / 200 | 击杀时在脚下爆出金币，数量 2~8 枚 |
| 通关 | +100 | 击杀第 5 阶 Boss 时结算 |

- 金币掉落后不会消失；跑图漏捡的，在死亡 / 通关结算时**自动收进本局金币**，保证「死亡全留」。
- 精英 12% 和通关 +100 是本次补充的细节，用来让「打精英 / 打通关」比单纯刷小怪更有收益；如果觉得偏离原意，可以只保留小怪 3% + Boss 固定掉落。
- 本局金币只在**结算时**写入槽位，避免每捡一枚写一次 `localStorage`。
- HUD 显示本局已拾取金币；天赋页显示槽位总金币。
- `?demo=1` / `?showcase` / 平衡脚本跑的是**直接模式**，不读写任何槽位，避免污染存档。

## 3. 天赋树结构

### 3.1 圆盘布局

- 圆心是职业徽记，不是可购买节点。
- 外圈三等分，每 120° 一个分支，分支之间留 4° 视觉间隙。
- 每个分支 6 环，节点数 `1 / 2 / 2 / 2 / 2 / 1`，共 10 个节点。
- 3 分支 × 10 = **30 个节点**，可投入 **84 级**（每分支 28 级）。
- 6 环半径按 `0.18 / 0.33 / 0.48 / 0.63 / 0.79 / 0.96 × R` 分布；分支名与进度放在左下角的三条进度条和悬停提示里，外圈只保留节点，避免小窗口文字压到节点。
- 节点半径约 `R × 0.058`（720p 下约 15px，1080p 下约 20px），悬停放大 1.15 倍。

单分支节点位：

| 环 | 节点位 | 角度偏移 | 类型 | 前置 |
|---|---|---|---|---|
| 1 | 核心 | 0° | 核心 | — |
| 2 | 技能 1 | -16° | 技能 | 核心 |
| 2 | 生命 | +16° | 生命 | 核心 |
| 3 | 技能 2 | -20° | 技能 | 技能 1 |
| 3 | 技能 3 | +20° | 技能 | 生命 |
| 4 | 力量 | -14° | 力量 | 技能 2 |
| 4 | 技能 4 | +14° | 技能 | 技能 3 |
| 5 | 技能 5 | -16° | 技能 | 技能 4 |
| 5 | 功能 | +16° | 功能 | 力量 |
| 6 | 终极 | 0° | 终极 | 技能 5 ≥ 2 级 且 功能 ≥ 2 级 |

- 前置只要求 **1 级**即可点亮下一节点；终极要求两个 5 环节点各 **2 级**。
- 三系共享金币，可跨系投资；**终极节点不互斥**，但 700 金/个，全点代价很高。
- 节点购买顺序只受前置限制，不限制「必须先点满一系」。

### 3.2 节点数据结构

```js
// js/talents.js 里 CONTENT.talentTrees.warrior.branches[0]
{
  id: 'arms',
  name: '武器',
  color: '#ffd166',
  angle: -Math.PI / 2,
  skills: ['heroic_strike', 'cleave', 'rend', 'sunder_armor', 'overpower'],
  nodes: [
    {
      id: 'arms.core',
      ring: 1, offset: 0,
      name: '武器精通', icon: '⚔',
      desc: '武器系技能伤害 +4%/级',
      cost: [50, 75, 110],
      req: [],
      effect: { branchDmg: 0.04 }
    },
    {
      id: 'arms.skill1',
      ring: 2, offset: -16,
      name: '英勇打击', icon: '⚔',
      desc: '英勇打击伤害 +8%、冷却 -3%/级',
      cost: [65, 95, 135],
      req: ['arms.core'],
      effect: { skills: { heroic_strike: { dmg: 0.08, cd: -0.03 } } }
    }
    // ...
  ]
}
```

效果字段统一为：

| 字段 | 含义 |
|---|---|
| `branchDmg` | 本系全部技能伤害加成（加法百分比） |
| `branchCdr` | 本系全部技能冷却缩减 |
| `hpPct` / `dmgPct` / `cdrPct` | 最大生命 / 全部伤害 / 全局冷却 |
| `armorAdd` | 护甲（减伤比例）直接加值 |
| `speedAdd` / `regenAdd` / `magnetAdd` | 移速 / 每秒回血 / 拾取范围 |
| `areaPct` / `xpPct` | 全局技能范围 / 经验获取 |
| `skills` | 指定技能的 `dmg / cd / area / duration / shield / buff / dot / heal / knock / slow / vuln / dist / internal` 修正 |
| `onKillHaste` | 击杀后短暂移速（狂怒终极） |

- 所有 `effect` 数值都是**每级**数值；聚合时乘以当前等级。例如 `branchDmg: 0.04`、3 级 = +12%。
- 节点 ID 由分支 + 槽位生成：`arms.core`、`arms.skill1..5`、`arms.vitality`、`arms.power`、`arms.utility`、`arms.keystone`；`skillN` 对应的具体技能看该节点的 `effect.skills`，同一节点可强化两个技能（余烬、霜甲）。
- `offset` 单位是**度**，布局时转弧度；负值在分支中心线左侧，正值在右侧。
- 双技能节点（余烬、霜甲）在 `skills` 里写两条目标，各自给不同修正；数值按半档设计（+4% / -2% / +5%）。
- `skillStats()` 只对存在的字段做乘法/加法，不会给没有 `shield` 的技能凭空加护盾。

### 3.3 购买 / 洗点规则

- 购买条件：`rank < cost.length`、`slot.gold >= cost[rank]`、所有前置节点 `rank >= 1`（终极为 `>= 2`）。
- 购买成功：扣金币、`rank++`、立即写存档、播放升级音效、节点脉冲。
- 金币不足：节点红闪 + 顶部提示「金币不足，还差 N」。
- 未解锁：悬停提示「需要：节点名 1 级」。
- 洗点：**整棵树**清零，返还 `floor(已投入 × 0.8)`；需要点击两次确认，避免误触。
- 已满级节点显示金色描边 + 3 格进度。

## 5. 本地存档

### 5.1 key 规划

| key | 作用 |
|---|---|
| `abyss.slots.v1` | 3 个槽位 + 当前激活槽；天赋、金币、记录、统计都在这里 |
| `abyss.best.v3` | **保留**：直接模式（测试、平衡、演示）写入的旧记录；启动迁移时读取 |
| `abyss.diff.v1` | **保留**：新槽位的默认难度；老玩家迁移时沿用 |
| `abyss.activeSlot.v1` | 不单独建，`active` 存在 `abyss.slots.v1` 里 |

### 5.2 数据结构

```json
{
  "version": 1,
  "active": 0,
  "slots": [
    {
      "id": 0,
      "classId": "warrior",
      "skin": 1,
      "difficulty": "normal",
      "gold": 320,
      "talents": {
        "arms.core": 3,
        "arms.skill1": 2,
        "arms.vitality": 1
      },
      "stats": {
        "normal":   { "time": 512, "kills": 1300, "level": 34, "classId": "warrior" },
        "hardcore": { "time": 0,   "kills": 0,    "level": 0,  "classId": "warrior" }
      },
      "totals": { "runs": 12, "wins": 2, "kills": 9300, "seconds": 4100, "goldEarned": 2840 },
      "createdAt": 1760000000000,
      "lastPlayed": 1760000000000
    },
    null,
    null
  ]
}
```

- `talents` 里不存在的节点视为 0 级；读取时按当前节点表裁剪等级，防止旧数据越界。
- `gold` 不允许为负数；购买天赋时扣减，结算时增加。
- `stats` 仍按难度分开；每槽绑定职业，所以记录天然按职业分开。
- `totals` 只用于槽位卡片展示，不参与数值。
- `difficulty` 按槽保存：战士槽可以常驻硬核，法师槽常驻正常。

### 5.3 迁移

1. 启动时先读 `abyss.slots.v1`；合法就直接用。
2. 不存在 / 解析失败 → 读 `abyss.best.v3`：
   - 有记录：创建槽位 0，职业取 `hardcore.classId || normal.classId || 'warrior'`，把两档记录放进 `stats`，金币 0、天赋空、形象 1、难度取 `abyss.diff.v1`。
   - 无记录：三个空槽。
3. **不删除** `abyss.best.v3`，迁移失败或想回退时还能找回。
4. 任一槽位字段缺失时用默认值补齐，绝不让坏存档导致白屏。

### 5.4 槽位生命周期

- **创建**：空槽 → 职业选择 → 形象选择 → 写入槽位（金币 0）→ 进入天赋页。
- **进入**：已有槽位 → 直接进天赋页；槽位卡片显示职业、金币、天赋点、两档最佳、上次游玩。
- **删除**：卡片右上角「删除」，点击两次确认；删除后当前槽若被删，自动切到第一个非空槽。
- **职业锁定**：建槽后不能换职业；要换只能删槽重建。
- **重复职业**：允许，例如两个战士槽分别走武器 / 防护。
- **命名**：v1 不支持自定义名字，槽位显示为「第 N 槽 · 战士 / 法师」；后续要改名再加输入框。
- **形象**：存在槽里；天赋页右上角可以切换 1/2 号形象并保存。
- **难度**：存在槽里；建槽过程中的难度选择写到即将创建的那个槽，创建后天赋页可继续切。
- **存档时机**：建槽、删槽、切槽、买/洗天赋、切难度、换形象、死亡/通关结算。
- **中途关页面**：本局未结算的金币不保留（避免刷新刷金）；已保存的天赋和总金币不受影响。

## 7. 平衡

### 7.1 只加强度，不碰卡池

- `rollOffers` / `applyOffer` 不改：15 技能仍然全部可随机出现，5 技能槽上限不变。
- 天赋只通过 `Player.recalc()` 和 `skillStats()` 生效，保证「点不点天赋，Build 玩法一致」。
- 升级卡面文案（`d.up`）保持基础数值；天赋加成在结算/属性面板体现，不逐卡改写，避免文案维护量爆炸。
- **已知副作用**：技能专属节点只有在本局抽到该技能时才有收益；因为不改卡池，这是有意接受的。若以后想要更稳定的 Build 导向，再单独讨论「起手技能选择 / 卡池权重 / 技能解锁」，不在本轮范围。

### 7.2 深渊侵蚀

- `stacks = floor(总天赋等级 / 10)`，最多 8 层（84 级）。
- 敌人生命 `× (1 + 0.012 × stacks)`，敌人伤害 `× (1 + 0.005 × stacks)`。
- 满级：敌人生命 **+9.6%**、伤害 **+4%**。
- 普通怪、精英、Boss、图腾、Boss 召唤物统一生效；技能本身不改。
- **为什么从 2.5%/1% 降下来**：满树本身只给 +60% 生命 / +27% 伤害 / +55~68% 技能强度，而旧的 +20%/+8% 侵蚀会吃掉其中一大块，导致「天赋越多，怪也越强」——和「一点点升天赋、逐渐轻松通关」的目标相反。现在的侵蚀只是「别让满树完全无脑」的轻量补偿，真正的挑战交给硬核难度。
- 天赋页与槽位卡仍然显示当前层数与实际百分比，避免「我变强了怎么怪也变强」的不透明感。
- 洗点后总等级下降，侵蚀随之下降；下一局生效。

### 7.3 封顶与防溢出

- 护甲沿用 `hurt()` 里 70% 上限；天赋最多把战士从 52%（被动满）推到 ~69%，不会免疫。
- 冷却缩减在 `Player.recalc()` 里 clamp 到 60%，避免多乘区叠出 0 冷却。
- 减速、易伤在 `skillStats()` 里做上限（减速 90%、易伤 100%）。
- 天赋等级读取时裁剪到节点 `cost.length`，改表不会让旧存档超模。

### 7.4 难度与模式隔离

- 难度倍率见 `js/content.js` 的 `CONTENT.difficulties`：正常是「学习档」，硬核是「满树之后的挑战」——密度 ×1.67（刷新间隔 ×0.60）、上限 420、精英 26s、每波后期 +2，敌人生命 ×1.40 / 伤害 ×1.20，Boss ×1.50 / ×1.30，但经验 ×0.55，不靠送等级来维持爽感。
- 4/5 阶 Boss 有狂暴计时（5 阶 70s、4 阶 85s，硬核 ×0.85）：到点回血 + 弹幕加密，再过 40s 伤害 ×1.25。这是一个单目标 DPS 门槛，让「打得太慢」变成「打不掉」。
- 硬核不额外加成金币（避免「为了金币被迫硬核」）。
- 演示 / 平衡 / 冒烟脚本走直接模式，不读槽位、不写槽位；`?talents=full` / `?talents=0..100` 只对直接模式生效，用来单独观察指定强度的天赋树。
- 正常模式只有从天赋页「开始挑战」才会带入槽位天赋和侵蚀。

### 8.4 兼容策略

- 保留 `GAME.start(classId, diff, skin)` 的直接模式语义，现有 40+ 个单测、`smoke.js`、`balance.js` 不改调用方式。
- 直接模式继续维护 `GAME.best` 和 `abyss.best.v3`，旧单测（`g.best.normal.time`）继续通过。
- 正常模式用 `startSlotRun()`，记录写 `slot.stats`，不覆盖 `abyss.best.v3`。
- 增加 `runMode = 'menu' | 'direct' | 'slot'`：`menu` / `slot` 下 `bestOf()` 读当前槽，`direct` 下读 `this.best`；`start()` 设 `direct`，`startSlotRun()` 设 `slot`。
- 金币复用 `Gem` 实体并打 `gold: true` 标记；`dropGem` 的 320 上限合并逻辑只在**同类型**里找目标，避免金币和经验混池。
- 流程单测需要改：标题不再直接进职业选择，而是进槽位页；建槽后进天赋页，再从天赋页开局。

### 8.6 性能

- 天赋树只在菜单绘制，30 节点 + 连线，开销可忽略。
- 金币实体数量：3% × 2000 击杀 ≈ 60 枚，远低于宝石上限 320。
- `skillStats()` 只对 5 个技能、每帧一次；无天赋时直接返回基础对象，不分配。
- 存档写入只在菜单操作和结算，不进入主循环。

### 8.7 实现差异与状态

- **节点 ID**：技能节点用 `branch.skillN`，没有按技能名生成；`skillN` → 技能映射写在 `effect.skills`，与 §4 的节点表一一对应。
- **金币 RNG**：直接模式完全不掉金币，也不消耗战斗 RNG；槽位模式的金币掉率用独立 `Math.random()`，不改变种子化战斗序列。这样 `balance.js` / `smoke.js` 的基线不因金币系统漂移。
- **金币拾取**：`Gem.gold` 复用经验宝石实体；死亡 / 通关时 `collectRemainingGold()` 自动收编地上金币，再写槽位，保证「死亡全留」。
- **槽位初始解锁**：`abyss.slots.v1` 首次启动会写 3 个 null 槽；旧 `abyss.best.v3` 存在时迁移到槽 1，旧 key 保留。
- **UI**：天赋页按 1280×720 设计，小窗口会隐藏左侧属性面板、压缩底栏按钮；分支进度固定放在左下三条进度条，悬停提示自动避让屏幕边缘。
